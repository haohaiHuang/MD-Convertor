# UI 评审 — 2026-09-20（版本 0.3.1）

评审对象：MD-Convertor 的网页 UI（Next.js 16 前端 + Electron 0.3.1 打包应用）。
方法：design-references 环节 4 快速通道（`references/ui-quickfix.md`），不重走调研/约束。
证据来源：源码（`globals.css` / `page.module.css` / `settings/page.module.css` / `page.tsx`）、
e2e server 的真实截图（1440 / 375 / 761–1024）、打包应用 CDP 截图、`getBoundingClientRect()`
实测、`Tab` 键盘焦点扫描、WCAG 对比度计算、`design_audit` + `design_contrast` 机器检查。

结论：**视觉方向是成立且有辨识度的**（纸色 + 墨绿 + 衬线正文预览，不像模板产物），
问题集中在「状态表达」与「同页尺度不统一」两类，共 6 条必须修、9 条建议修。
没有需要推翻重做的方向。

> **最终决定（2026-09-20，用户）：以上全部不整改。** 用户看过对照板（现状截图 vs CSS
> 模拟，临时文件，用户看过即删）后认为现状可接受，不值得为此改动。
> 本文件自此为**已归档的评审记录**，不是待办清单：不要在没有新证据、
> 也没有用户指认具体条目的情况下重提这批发现。代码零改动，
> `settings.json` 在校验探针前后 SHA-256 一致。

## 1. 方向锁（评审基准，不是待改项）

- 使用者与场景：个人在本机把网页/粘贴内容转成 Markdown，高频重复使用的工具页。
- 美学方向：纸质编辑风（暖白底 `--paper #f7f5ef`、墨绿 `--accent #176b5d`）、
  正文预览走衬线（Georgia + 宋体回退），UI 走无衬线（Inter）。
- 设计签名：左侧「MD」墨绿方块品牌标 + 全角标点中文大标题（半句染绿）+ 衬线预览区。
- 硬约束：单机、不上传、无历史；正文预览是可读文档，不是装饰。
- 签名微交互：转换中按钮切换为「停止转换」（悬停填充红）、结果区平滑滚入。

下述判断都以这个方向为基准；下面所有「修」都不改变方向。

## 2. 必须修（P0，用户可见且影响可用性）

### P0-1 禁用态主按钮不可读（实测 2.51:1）
`page.module.css` `.submit:disabled` 用整元素 `opacity: .55`，白字压 accent 后
有效色 ≈ `#fbfaf8` on `#7ca99f` = **2.51:1**，远低于 4.5:1。
空输入时它是首屏最大的色块（1440 与 375 都如此），读起来像「渲染坏了」。
- 修：disabled 改用 `--accent-soft` 底 + `--muted` 字（4.2:1），或描边 + muted 字。

### P0-2 placeholder 对比度 2.71:1，而它是空态唯一的提示
`#929b98` on `#f7faf8` = **2.71:1**（`.input` / `.textarea` / `.sourceInput`
三处同一色值）。粘贴面板的 textarea 是 **350px 无边框空白**，placeholder 是唯一线索。
- 修：换成 `--muted`（4.71:1）或 `#6b7472`；三处一起改。

### P0-3 自定义焦点环只有 1.31–1.44:1
实测 `Tab` 扫描（`document.activeElement` 的 computed outline）：
- 有自定义焦点的地方反而最弱：home `.input:focus-visible`（24% accent inset shadow）
  ≈ 1.44:1，settings `.input:focus-visible`（18% accent outline）≈ 1.31:1，
  均低于 WCAG 非文本 3:1。
- 未自定义的按钮/链接回落浏览器默认蓝环 `rgb(0,95,204)`（5.98:1）：
  「转换」「保存」「拉取模型」「返回转换」「清空链接」「重新扫描」、全部
  checkbox/radio 都是蓝环 —— 能看见，但在绿/纸色系里是外来色。
- 唯一正确的一处是 `.modeTab:focus-visible`（`2px solid var(--accent)`，6.37:1）。
- 修：全站统一 `.modeTab` 那个写法（`outline: 2px solid var(--accent); outline-offset: 2px`），
  删掉两个半透明的替代方案。

### P0-4 分段控件选中态几乎不可见（填充差异 1.03:1）
`[class*=modeTabs]` 轨道 `rgba(255,255,255,.58)` 叠纸色 ≈ `#fcfbf8`，
选中 pill 纯白 `#ffffff` → **1.03:1**。选中语义实际由文字承担（ink 15.25:1 vs muted 4.71:1）
加一层 8% 阴影。这个控件在同一屏出现两次（输入模式切换 + 原文/译文），
且两处外观完全相同。
- 修：选中 pill 加 `1px solid var(--line)`，或轨道改用 `--accent-soft`；
  顺带把结果区的 tab 与输入模式的 tab 做出层级差（结果区不必满宽）。

### P0-5 同页三种内容宽度：720 / 820 / 1180
实测：错误卡 `max-width 720`（x≈347，宽 695）；表单列 x=310 w=820；
结果区 (`.stats` / `.preview` / 结果 tab) x=130 w=1180。
转换完成后视线要在三种左边距之间横跳，结果区看着像另一个页面贴上来。
- 修：结果区并入 820 列（推荐）或全page统一 1180；错误卡跟随同一列。

### P0-6 正文行宽 1050px @17px（CJK 约 62 字/行）
`.preview` 内容宽实测 1050px，17px 衬线行高 1.86（31.6px）。
CJK 62 字/行、拉丁约 130 字符/行，都远超舒适区（CJK 25–40、拉丁 45–75）。
- 修：`.preview` 内层正文 `max-width: 46rem`。这是「阅读表面」的核心参数，优先级高于观感微调。

## 3. 建议修（P1）

1. **错误态字段没有视觉标记**：`aria-invalid` 代码里有（a11y 正确），但两个 CSS 模块
   都没有 `[aria-invalid="true"]` 规则 → 输入框看不出错，只有下方 13px 红字
   （截图 `05-home-invalid.png`）。
2. **`prefers-reduced-motion` 不一致**：`returnToTop`（`page.tsx:491`）尊重，
   转换后自动 `scrollIntoView({behavior:"smooth"})`（`page.tsx:302`）不尊重。同一文件两套标准。
3. **设置页 5 张同款卡片**：白底、18px 圆角、同一 `--shadow`(0 22px 60px)
   重复 5 次 → 模式选择（全局）与密钥字段（细节）视觉同级，页面成一条平地。
   ui-quickfix 明令的「通用圆角阴影卡片栅格」。建议：分区只用分隔线与标题，
   卡片保留给真正需要框住的表单项（Provider 内层面板）。
4. **`--surface-muted` 是死 token**：`settings/page.module.css:154` 用
   `var(--surface-muted, #fbfbfa)`，`globals.css` 从未定义该变量。
   且该内层面板与卡片面 `#fffefa` 只差 **1.03:1**，分组几乎不可见。
5. **导航不一致**：首页「设置」= 有边框胶囊（38px 高 / 11px 圆角）；
   设置页「返回转换」= 无边框绿字（0px 圆角，`.backLink`）。
6. **「未配置」徽标语义不清**：实测卡片里名称 / Base URL / 模型都填好了，
   只有密钥缺失（`secrets.json` `entries: {}`），徽标却写「未配置」，
   读起来像整张卡都没配。建议改「未保存密钥」，或把徽标移到密钥行。
7. **「保存」缺脏标记**：feat-029/030 之后「保存」是 Provider 唯一的落盘入口，
   但它与旁边的「拉取模型」同为白底描边次级按钮，改完字段没有任何未保存提示。
8. **首次粘贴会跳动**：「清空」行与「内容已修改…」提示只在有内容时出现，
   首次粘贴后下方内容整体下移。
9. **375px 细节**：H1 `line-height: 1.04` + `letter-spacing: -0.055em` ——
   负字距是拉丁展示字手法，用在中文大标题会让 `，` 后出现异常空隙（截图可见），
   1.04 行高让两行中文几乎相贴；URL placeholder 被截断成 `example.co`；
   设置页「拉取模型」按钮文字折成两行。

## 4. 观察：判定为「不成问题」，不要按机器报告改

- **`transition: all`（审计误报）**：`transition-property` 的 CSS 初始值就是 `all`
  （时长 0s），不是声明。实际三个模块只过渡 color / background / box-shadow / transform，
  没有违规。
- **body 的 radial + linear 渐变**：ui-quickfix 把渐变列为 slop 信号，但这里是 9% 顶角
  径向光营造纸质氛围，不承担信息，与 `--paper`/`--shadow` 自洽。要做减法这是第一顺位，
  但收益最低 —— 不建议为它单独开一轮。
- **Inter 声明但未随包加载**：本机 `~/Library/Fonts` 装有 Inter，实测渲染确实走 Inter
  （同一串文本 Inter 212.11px vs 系统字体 204.16px），没有静默失效。换台没装的机器会回落，
  对单机自用无影响。
- **`blockquote` 的 3px 左边线**：编辑排版惯例，不是「粗侧边强调线」滥用，保留。
- **圆角 5 档（10/11/12/14/18）、间距 24 档、无 token 层**：是维护性问题不是视觉缺陷。
  若要修，只加 6 个变量（`--radius-card/--radius-control`、`--space-2/3/4/6`、
  `--shadow-card/--shadow-raise`）即可，不要引入 Tailwind 或 token 生成器。
- **`design_contrast` 只报出 1 条**（「有颜色无配对背景」）：因为 CSS 模块大量用变量与继承，
  该工具覆盖不到；本报告的对比度数值是手工按 WCAG 公式算的，以此为准。
- **`design_audit` 报 133 条 / BLOCK**：包含上述误报与结构计数（圆角档位、字族链长度），
  不能直接当缺陷清单用，需逐条人工裁决。

## 5. 明确不建议做（防范围蔓延）

- 不要把界面改成 macOS 原生外观（Native exception：这是 Electron 承载的既有 Web UI，
  整体迁移是重写而非优化）。
- 不要为「统一 token」引入 Tailwind / 组件库 / 样式生成器。
- 评审阶段不要动 `e2e/home.spec.ts` 的像素断言（转换按钮右边缘与粘贴框右边缘差值 < 4px，
  且与「来源 URL」输入框同行）。它锁的是 feat-031 里用户明确要的效果 ——
  要改 `sourceInput` 的 `flex`、按钮宽度或 `.sourceRow` 的 `gap`，先改断言。
- 不要为了 P0-5 把表单列从 820 加宽：结果是阅读表面，820 是合适的；应让结果区收窄。
