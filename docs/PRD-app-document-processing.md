## 1. 背景与目标

桌面端现在一次只处理一篇文章：给一个 URL 或粘贴一段富文本，得到一份 Markdown。

浏览器插件（B）会把文章连同图片一起攒进一个目录。这些 `.md` 还需要**加工**才能当成品用：图片还挂在网上、内容可能不是中文。桌面端要能一次处理一批本地 `.md`。

目标（用户价值）：

1. 一次处理一批 Markdown，不用一篇篇手动打开。
2. 加工后得到**自包含**的文档：图片在本地、正文在目标语言。
3. 已经处理过的文件不重复处理。

**这是一项通用能力**：不绑定插件 —— 任何目录下的 `.md` 都能处理。

## 4. 非目标

- 不做批量下载网页（只处理已经在本地磁盘上的 `.md`）。
- 不改变现有单篇转换流程的行为。
- 不引入新的 Provider 或翻译引擎（复用现有）。
- 不做定时 / 后台自动处理。
- 不做递归扫描子目录、不做文件预览、不处理 `.md` 以外的格式、不检测「产物被手工编辑过」（细节见 FSD §3）。
