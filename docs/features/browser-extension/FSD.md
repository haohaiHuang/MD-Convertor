## 1. 场景（已明确的部分）

在浏览器里读到好文章时，一键把**当前页面**转成 Markdown：用当前已登录的会话抓取（这样付费墙内 / 需登录的内容也能工作），本地预览，下载 `.md`，可选翻译。

**必须守住的边界**：

- 只读**当前页面 DOM**，不读 Cookie、不读登录凭据、不绕过访问限制、不做自动翻页爬取。
- 内容不离开本机；翻译是用户自己配置的端点（与桌面端同一口径）。
- 富文本粘贴转换只处理用户主动复制的内容 —— 与桌面端现状一致。

## 2. 三个必须先决定的问题

### 2.1 放哪、怎么构建

仓库现在是「Next.js + Electron 单产物」。扩展是**新的交付物**：独立的 manifest、独立的构建（MV3 打包）、独立的发布方式。

- 影响：`AGENTS.md` 的平台边界现写「只构建和验收 `darwin/arm64`」，要同步修订；`init.sh` 的验证面是否纳入扩展构建，也是一个决定。
- 选项：同仓库新增 `extension/` 目录 / 独立仓库 / 先只在本地加载不发布。

### 2.2 Provider 密钥放哪

桌面端的密钥在 `safeStorage` 加密的 `secrets.json` 里（Electron 主进程专属），**扩展无法复用**。

- 影响：这决定了翻译在插件里怎么做。若密钥无处可放，插件的翻译只能走「无密钥」路径。
- 选项：`chrome.storage.local`（**明文**，需在文档里明说）/ 每次输入不持久化 / 插件不做翻译、只导出。

### 2.3 代码如何共享

Readability + Turndown 管线现在是服务端模块（`src/lib/**`）。

- 影响：复用同一套代码 vs 重写一套，工作量差一个量级，也决定两边行为是否会漂移。
- 选项：抽成无 Node 依赖的共享包 / 扩展内单独实现 / 扩展只把 DOM 交回本机服务处理（但这样就需要一个常驻服务，与「不想开桌面应用」的初衷冲突）。

## 3. 已定的方向性约束（不是问题，是边界）

1. **Chromium 内核，MV3**。
2. **与桌面端同源的产品口径**：不读登录态、不绕过限制、内容不外传。
3. **独立版本线**：作废文档里写的 `v0.5.0 / v0.6.0 / v0.7.0` 不采纳 —— 桌面端门禁硬校验唯一目标版本，当前在 `0.3.x` 线上，跳号没有收益。
4. **独立文档管理**：本方向不与视觉刷新（`docs/features/ui-refresh/`）共用阶段文档或 feature 条目。
