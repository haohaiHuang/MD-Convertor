# MD-Convertor v0.3.9 UI/UX 走查报告

## 1. 走查范围与方法

逐张查看 9 张截图（浏览器模拟 01/02/03/04/05 + 真实 Electron 10/11/12/13，忽略左下角 "N" 徽标），并 Read 源码逐条核实：page.tsx / page.module.css、local-docs/panel.tsx / panel.module.css、settings/page.tsx / settings/page.module.css、globals.css、layout.tsx。以下每条结论均有截图现象或代码行号佐证。核实说明：12-desktop-convert.png 为转换页、13-desktop-settings.png 为设置页，与文件名一致（截图管线曾出现视觉去重误显，已用像素级布局核对确认，不影响结论）。

## 2. 用户两点的判定与具体修改建议

### 点 1「MD-Convertor 的标题居中比较好」—— 同意，建议改

**现状**：page.tsx L624-647，顶栏结构为 `.headerLeft`（86px 的 `.backSlot`/`.backButton` + gap 16px + `.brand`）+ 右侧 `.settingsLink`。品牌字固定落在左侧（1180 窗口实测约 x≈149px），距页面中心约 390px。

**判定**：合理。居中后品牌在所有页面共用视口中轴，顺带消除设置页与主界面品牌字横向跳动（设置页 shell 860px、主界面 shell 1086px，目前品牌位置逐页漂移）。

**改法**（page.module.css + page.tsx 三行 DOM 调整）：
1. 把 `.brand`（page.tsx L639-641）移出 `.headerLeft`，成为 `.header` 的第二个直接子元素；
2. `.header` 改三列网格（page.module.css L11-16）：
```css
.header {
  display: grid;
  grid-template-columns: 1fr auto 1fr;
  align-items: center;
}
.headerLeft { justify-self: start; }
.brand { justify-self: center; }
.settingsLink { justify-self: end; }
```
3. `.backSlot` 86px 机制保留（仍防左列宽度跳动）；
4. settings/page.module.css `.header` 套同一网格，品牌同样居中，跨页不再跳。

**备注**：居中后与居中的 hero 大标题形成双中轴，但品牌仅 15px、`--ink` 深色，视觉竞争有限，可接受。备选方案是品牌左缘对齐内容列（x=180）也能消除跳动，但不符合你的居中偏好，仅备录。

### 点 2「返回和设置按钮和下方的框体没有对齐」—— 同意，给出低成本对齐方案

**现状**（1180×820）：`.page` 两侧 padding 约 47px，`.shell` 1086px；`.header` 横跨整条 shell，返回按钮左缘 x≈47、设置按钮右缘 x≈1133；而下方 `.modeTabs`/`.form`/`.entryGrid` 均为 max-width 820px 居中（x=180–1000），两侧各外凸约 133px。文档处理面板 960px（x=110–1070）也各差约 63px。你判断"不是大问题"也对——纯观感问题，不影响操作。

**低成本方案（推荐，主要改 CSS）**：先统一内容列宽，再让顶栏贴合内容列。
1. globals.css 增加 `--col: 960px;`（取现有最宽列；若嫌转换表单变宽过松，取 880px 并把 panel 960→880 亦可）；
2. page.module.css：`.header` 加 `width: min(var(--col), 100%); margin-inline: auto;`；`.entryGrid`/`.modeTabs`/`.modePanel`/`.form`/`.subtitle`/`.translateToggle`/`.validation` 的 max-width 820px → `var(--col)`；`.hero` 960px → `var(--col)`；
3. panel.module.css：`.panel`/`.degraded` 960px → `var(--col)`；
4. settings/page.module.css：`.shell` 860px → `var(--col)`。

效果：返回/设置与框体左右缘对齐，三个页面共用同一栅格，点 1 的居中轴也复用它。风险低：`.form` 是 flex，820→960 无断点问题，表格更宽松。
**不推荐**：让顶栏各自贴 820/960/860——按钮位置会在页间跳动，治标复发。

## 3. 新发现问题清单

**P0（体验阻断）：无。**

### P1（明显问题，7 项）

**P1-1 阻断原因提示视觉过弱 + 位置游离**（状态与反馈）
- 画面：11-desktop-local-docs.png
- 证据：「还没有设置输出目录，先到设置里选一个。」以 `--muted` 灰色 13px 小字单独挂在右对齐工具行之下、左缘悬空；「一键转换」disabled 仅靠 opacity 0.55 表达。panel.tsx L245-255：`no-output` 走 `styles.hint`（灰色），仅 `same-dir` 才给 `styles.hintWarning`（琥珀色）；L317-326 hint 渲染在 toolbar 之后。
- 影响：核心任务被阻断的原因最容易被漏看，用户只看到灰按钮不知所以；提示里的「设置」不可点击，还得自己找入口。
- 建议：① `no-output` 同样套 `.hint .hintWarning`（`--warning: #8a5a12` 已就位）；② notice 移到 `.toolbar` 之前（或紧贴按钮组正下方右对齐）；③ 文案改动作：追加 `.button`「去设置」跳 `/settings?from=local-docs`（page.tsx L622 `settingsHref` 模式可复用）。涉及 panel.tsx L245-255/L317-326、panel.module.css `.hint`/`.hintWarning`。

**P1-2 本地代理「未检测到」与「启用」矛盾态**（状态与反馈）
- 画面：05-settings-full.png / 05-settings-top.png / 13-desktop-settings.png
- 证据：settings/page.tsx L656-669，`cli.detectedPath ?? "未检测到"` 与 `cli.enabled` 的「启用」勾选框并排独立渲染，未检测到仍可保持勾选（截图中 pi、claude 均为「未检测到」+「启用」已勾选）；「未检测到」还套用 `.path`（ink 深色 12.5px 等宽），与真实路径同款样式。
- 影响：状态语义矛盾（"启用"一个不存在的 CLI），错误成本后移到翻译执行时才暴露。
- 建议：① 未检测到时 checkbox `disabled` 且强制不勾选；② 新增 `.pathMissing { color: var(--muted); }` 或复用 `.badge` 区分状态文本；③ radio 行加 12px 状态点（已检测=accent、未检测=muted）。涉及 settings/page.tsx L640-699、settings/page.module.css。

**P1-3 设置页返回文案与实际去向不符**（文案）
- 画面：05-settings-full.png、13-desktop-settings.png
- 证据：settings/page.tsx L374 固定渲染「返回转换」，但入口 URL 带 `?from=`（page.tsx L622），从首页/文档处理进入时实际返回首页/文档处理（L154 注释已承认该机制）。
- 影响：文案与结果不符，用户预期被误导。
- 建议：按 `from` 映射文案——home→「返回首页」、local-docs→「返回文档处理」、convert→「返回转换」、缺省→「返回」。一行映射即可（settings/page.tsx L374）。

**P1-4 同排控件尺寸不一致**（控件一致性）
- 画面：全部主界面截图
- 证据：page.module.css `.backButton` min-height 34px / 13.5px / radius 11px（L46-62）vs `.settingsLink` height 38px / 14px / radius 11px（L78-91）；panel `.button` padding 9px 14px / 13.5px / radius 10px；checkbox 16px（page/panel）vs 17px（settings/page.module.css L284-288）。
- 影响：顶栏两枚按钮 34px vs 38px 高矮不一，是最显眼的一处"拼凑感"。
- 建议：统一为 height 36px、font-size 13.5px、radius 10px；checkbox 一律 16px；可在 globals.css 抽 `--control-h` / `--radius-control` 变量。

**P1-5 页间顶栏形态两套、返回方位相反**（控件一致性/对齐栅格）
- 画面：05-settings-top.png vs 02-convert-link.png
- 证据：主界面 = 左侧胶囊「← 返回」+ 右侧「设置」胶囊（page.module.css `.backButton`/`.settingsLink`）；设置页 = 纯文字 accent 色「返回转换」无边框且在**右侧**（settings/page.module.css `.backLink` L28-42）。
- 影响：同一产品的导航控件形态与方位都变了，返回动作在两页出现在相反角落。
- 建议：设置页复用主界面顶栏语言——左侧胶囊「← 返回」（同 `.backButton` 样式），品牌居中（见点 1），右侧保留 `saveStatus`；淘汰 `.backLink` 纯文字样式。涉及 settings/page.tsx L370-376、settings/page.module.css。

**P1-6 转换页对齐轴不统一**（对齐与栅格）
- 画面：02-convert-link.png / 03-convert-paste.png / 12-desktop-convert.png
- 证据：「翻译为简体中文」勾选行贴内容列左缘（`.translateToggle`，page.module.css L522-532），紧邻下方产品特点行「✓无需登录 ✓图片内嵌 ✓随用随走」却居中（`.hintRow` justify-content: center，L446-453）。
- 影响：同屏两行同类辅助信息分居两种对齐轴，视线左右跳。
- 建议：二者同轴。推荐整组左对齐（`.hintRow` 改 `justify-content: flex-start`，与 `.translateToggle` 同宽 `var(--col)`）；若想保留"产品宣言"居中感，则把 `.translateToggle` 也居中。二选一，不要混。

**P1-7 首页入口卡正方形留白失衡**（留白节奏/层级）
- 画面：01-landing.png / 10-desktop-home.png
- 证据：`.entryCard` `aspect-ratio: 1/1`（page.module.css L142-156），卡内仅 22px 标题 + 两三行说明，垂直居中后上下各留约 130px 空白（卡高约 365px vs 内容约 100px）。
- 影响：首屏两张"空"方卡，视觉重量全在外框，内容显得稀薄。
- 建议：去掉 aspect-ratio，改 `min-height: 220px` + `padding: 28px 24px`（L845 的 760px 断点已有 `aspect-ratio: auto` 先例）。

### P2（打磨项，6 项）

- **P2-1 浏览器态设置页重复提示**（文案）：settings/page.tsx L432 与 L481 两处 `<p className={styles.cardNote}>目录选择只能在桌面应用中使用。</p>`，输入卡与输出卡同屏各一次 → 保留一处（建议页面级或仅输入卡），删另一处。
- **P2-2 占位符对比度偏低**（可访问性）：`.input::placeholder`/`.textarea::placeholder` 用 `#939ba9`（page.module.css L296/345/377），对白底约 2.8:1，低于 AA 4.5:1（其余正文 `--muted #565e6b` 约 7:1 达标）→ 改 `#767f8f`（≈4.6:1）。
- **P2-3 表格状态列视觉化**（状态与反馈）：「新」仅 muted 灰字（panel.module.css `.badge` L180-182）→ 做成小 chip（复用 `.pill` 样式）：新=accent-soft、失败=`.failed` 已有。
- **P2-4 hero 标题与 UI 同用 Inter 栈**（特异性加分项）：globals.css body 为 Inter+PingFang；产品已有 Michroma `--font-brand`（layout.tsx）与预览 Georgia/serif 的对比。可选给 `.title` 引展示字（如预览同款衬线）；克制风格下保持现状亦成立，属打磨而非错误。
- **P2-5 `.hintRow` 的 ✓ 为文本字形**（page.module.css L445-460）：现状克制可不动；若后续扩展建议换内联 SVG 对勾统一线重。
- **P2-6 圆角档位偏多**：10/11/12/14/16/18/999 七档并存 → 建议收敛为 10（控件）/16（卡片）/999（pill）三档，属体系化收尾。

**可访问性做得好的部分（顺带一句）**：aria-label 完整（返回首页/设置/翻译产物/全选/设为当前 CLI）、提示行 `role="status"`、`.srOnly`、`:focus-visible` 全覆盖、截断路径带 `title`、`lang="zh-CN"`、`prefers-reduced-motion` 降级（page.module.css L866-869，spinner 降速至 1.5s）、760px 响应式断点。待补：禁用原因通过 `aria-describedby` 挂到「一键转换」（P1-1 修复时顺带）。

## 4. 五维评分与 Anti-Slop 门控

| 维度 | 评分 | 一句话理由 |
|------|------|-----------|
| 设计哲学 | 4/5 | "安静的本机工具"理念清晰（浅灰渐变+白卡+蓝灰单主色+大留白），代码注释可见取舍记录，但三套列宽/两套顶栏说明未贯彻到系统层 |
| 视觉层次 | 4/5 | hero→表单→辅助信息视线流动明确、焦点唯一；但阻断提示该强反弱、首页卡内部上下失衡 |
| 执行质量 | 3.5/5 | 细节工艺高（截断、focus-visible、aria、reduced-motion），但控件度量/列宽/顶栏跨页不一致 |
| 特异性 | 4/5 | Michroma 品牌字 + 「干净的文档」蓝灰签名色 + 克制胶囊，辨识度成立；设置页另一套顶栏稀释了品牌一致性 |
| 克制 | 4/5 | 无冗余装饰、色彩仅蓝灰+警示两系、Less is More；✓ 特点行与正方卡留白略超必要 |

**总分：19.5/25**

**Anti-Slop 检测**：P0 = 0（无紫/彩虹渐变、无编造数据、无 emoji 顶图标、无圆角卡+彩边 AI 套路、无手绘插画、无破版、正文对比度达标、有响应式 + reduced-motion 降级）；P1 = 2（Inter 兼任展示字体、占位符对比度 2.8:1 边缘项——仅占位符，正文全部达标，故不计 P0）；P2 = 1（圆角七档）。**Anti-Slop 门控：通过。**

**总结论：有条件通过。** 无阻断项、视觉语言成熟，但走查 P1 共 9 项（新发现 7 + 用户点名 2）超过「P1 ≤ 3」的发布线，建议完成一轮低成本修正后再发版。

## 5. 优化优先级建议

**A. 只改 CSS（含个别 className/一行文案）即可落地：**
1. 品牌居中：`.header` 三列网格 + `.brand` 移出 `.headerLeft`（点 1）
2. `--col` 统一列宽 + 顶栏贴合内容列（点 2 + 消除页间跳动）
3. 顶栏按钮 34/38 → 统一 36px；radius 统一 10px；checkbox 统一 16px
4. `no-output` 提示加 `.hintWarning` 警示色 + 移位到工具行前
5. `.hintRow` 与 `.translateToggle` 同轴
6. `.entryCard` 去 aspect-ratio → min-height 220px
7. placeholder `#939ba9` → `#767f8f`
8. 「未检测到」文本 `.path` → `.pathMissing`（muted）
9. 返回文案按 `from` 映射（一行三元）
10. 删一处重复的「目录选择只能在桌面应用中使用。」

**B. 需动交互/结构：**
1. 设置页顶栏并入主界面顶栏语言（胶囊返回左置 + 品牌居中 + saveStatus 右置）
2. `no-output` 提示内加「去设置」跳转按钮 + `aria-describedby` 挂禁用原因到「一键转换」
3. 未检测到的 CLI 自动禁用/取消「启用」，radio 行加检测状态点
4. 表格状态列 chip 化（新/已完成/失败）
5. 若 hero 标题换展示字体，需连带复查 nowrap 断点（page.module.css L861-864）
